# 1309. C# files carry a two-line SPDX header that the build checks

- **Status:** Accepted
- **Date:** 2026-11-01
- **Deciders:** NCode Group
- **Refines:** [project-template ADR-0100](project-template/0100-warnings-are-errors-in-every-project.md)

## Context

Every C# file states its copyright and license in a header. A header that nothing checks drifts from file to file:
layouts diverge, a missing header goes unnoticed and a year goes stale.

The IDE0073 analyzer compares a file's header with the `file_header_template` that `.editorconfig` sets, and it is the
build's way to enforce one. The template cannot hold the Apache boilerplate: Roslyn's `.editorconfig` parser ends a value
at either `;` or `#` (its property pattern in `AnalyzerConfig.cs`), and the notice reads `(the "License");`, so the
analyzer would compare a three-line header and never match. A template cannot vary a year either. The project template's
own `file_header_template` is cut the same way
([NCodeGroup/project-template#215](https://github.com/NCodeGroup/project-template/issues/215)).

The warnings-are-errors rule of
[project-template ADR-0100](project-template/0100-warnings-are-errors-in-every-project.md) turns any analyzer at
`warning` into a build failure, in production and test projects alike.

## Decision

Every C# file starts with exactly these lines, followed by a blank line:

```csharp
// Copyright © NCode Group
// SPDX-License-Identifier: Apache-2.0
```

There is no `#region` and no year, so a year never goes stale in a file.

The repository's own `[*.cs]` section of `.editorconfig` sets
`file_header_template = Copyright © NCode Group\nSPDX-License-Identifier: Apache-2.0` and raises `IDE0073` to `warning`.
It comes after the template's section, which sets the same template at `suggestion`, so it wins for both keys and keeps
the header this repository's decision.

With warnings as errors, a missing or different header fails the build, in production and test projects alike.

Generated code is exempt: EF Core migrations are `generated_code = true` in `.editorconfig`, and the analyzer skips a
file that starts with `// <auto-generated`.

`NCode.Identity.slnx.DotSettings` carries the same header text, so Rider's code cleanup writes the header that Visual
Studio and the `IDE0073` fix write.

The `file_header_template` value contains neither `;` nor `#`, because Roslyn's `.editorconfig` parser ends a value at
either. The Apache boilerplate reads `(the "License");`, so it can never be the template.

The full license text stays in `LICENSE.txt`. The SPDX identifier is the machine-readable form of the license that
tools such as SPDX and REUSE read.

## Options considered

- The full Apache boilerplate, unenforced. Rejected: layouts drift, missing headers go unnoticed and years go stale.
- The boilerplate as `file_header_template`. Rejected: Roslyn cuts the value at the first `;`, so it never matches a
  file.
- The boilerplate without its `;`. Rejected: it alters the license notice that the header states.
- A two-line SPDX header (chosen): it has no `;` or `#`, it holds no year, one template expresses it, and the build
  enforces it.

## Consequences

- A new file gets the header from Visual Studio, Rider or the `IDE0073` fix, and a file with a missing or different
  header fails the build.
- The header has no year, so a year never goes stale in a file.
- The `file_header_template` value must contain neither `;` nor `#`, which Roslyn reads as the end of the value.
- The repository's own `[*.cs]` section, which comes later in `.editorconfig`, wins for `file_header_template` and
  `IDE0073`, so the header stays this decision's if the template's section changes.
