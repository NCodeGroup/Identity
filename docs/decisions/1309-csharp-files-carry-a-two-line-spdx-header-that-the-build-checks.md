# 1309. C# files carry a two-line SPDX header that the build checks

- **Status:** Accepted
- **Date:** 2026-11-01
- **Deciders:** NCode Group
- **Refines:** [project-template ADR-0100](project-template/0100-warnings-are-errors-in-every-project.md)

## Context

Every C# file states its copyright and license in a header. Three layouts of a `#region Copyright Preamble` block carry
a dated Apache 2.0 notice, with the years 2023 to 2026 and `@` where the copyright sign belongs, and nothing checks
them, so they drift from file to file.

The IDE0073 analyzer compares a file's header with the `file_header_template` that `.editorconfig` sets, and it is the
build's way to enforce one. The template cannot hold the Apache boilerplate: Roslyn's `.editorconfig` parser ends a value
at the first `;` (its property pattern in `AnalyzerConfig.cs`), and the notice reads `(the "License");`, so the analyzer
compares a three-line header and never matches. A template cannot vary a year either, and the block is three layouts
rather than one. The project template's own `file_header_template` is cut the same way
([NCodeGroup/project-template#215](https://github.com/NCodeGroup/project-template/issues/215)).

The warnings-are-errors rule of
[project-template ADR-0100](project-template/0100-warnings-are-errors-in-every-project.md) turns any analyzer at
`warning` into a build failure, in production and test projects alike.

## Decision

Every C# file starts with exactly these lines, followed by a blank line:

```csharp
// Copyright © NCode Group
// SPDX-License-Identifier: Apache-2.0
```

There is no `#region` and no year. `.editorconfig` sets the same text as `file_header_template` in the repository's own
`[*.cs]` section and raises `IDE0073` to `warning`, so a missing or different header fails the build. Generated code is
exempt: EF migrations are `generated_code = true`, and a file that starts with `// <auto-generated` is skipped by the
analyzer. `NCode.Identity.slnx.DotSettings` carries the same header text, so Rider's code cleanup writes the header
that Visual Studio and the `IDE0073` fix write.

The full license text stays in `LICENSE.txt`. The SPDX identifier is the machine-readable form of the license that
tools such as SPDX and REUSE read, and the copyright line is the one the project template renders.

## Options considered

- The full Apache boilerplate, unenforced. Rejected: the three layouts drift, nothing catches a missing header, and the
  years go stale.
- The boilerplate as `file_header_template`. Impossible: Roslyn cuts the value at the first `;`, so `IDE0073` never
  matches a file.
- The boilerplate without its `;`. Rejected: it alters the license notice that the header states.
- A two-line SPDX header (chosen): it has no `;` or `#`, it holds no year, one template expresses it, and the build
  enforces it.

## Consequences

- A new file gets the header from Visual Studio, Rider or the `IDE0073` fix, and a branch whose new file has the old
  header fails the build.
- The header has no year, so a year never goes stale in a file.
- The `file_header_template` value must contain neither `;` nor `#`, which Roslyn reads as the end of the value.
- Since project-template v0.57.1 the template's first `[*.cs]` section sets the same `file_header_template`
  ([NCodeGroup/project-template#215](https://github.com/NCodeGroup/project-template/issues/215)). The repository's own
  section, which comes later in `.editorconfig`, still sets it and wins for the key, so the header stays this
  decision's if the template's changes, and raises `IDE0073` from the template's `suggestion` to `warning`.
- Files that start with a UTF-8 BOM lose it with their header, as `charset = utf-8` in `.editorconfig` says.
